# ADR 0026: A Generated Artifact Derives From Templates and Source, Never From Project Data

**Status:** Proposed (authored 2026-07-28; ratification is the owner's)
**Date:** 2026-07-28
**Deciders:** Matthew-Hope Eland
**Relates to:** [ADR 0018 — A Generated, Bounded, Self-Retiring Style Layer for Injected IR Content](0018-transitional-ir-content-style-layer.md) (**this ADR amends it**: it adds a derivation constraint ADR 0018 left unstated); [ADR 0016 — The Canonical IR Carries Rendered Prose HTML](0016-ir-carries-rendered-prose-html.md) (the IR channel the durable fix rides); [ADR 0025 — `retired` Is a Terminal Story Stage in Both Classifiers](0025-retired-is-a-terminal-story-stage-in-both-classifiers.md) (the stage vocabulary whose domain is duplicated here); Stories 23.3 (authored the layer), 23.5 (put its gate into CI), 23.4 (retires the layer)

**Numbering note.** `docs/adrs/` ends at **0025** on disk. **`0019` remains claimed-but-unwritten** by Story 18.3, per the numbering note in [ADR 0023](0023-agent-facing-analysis-observation-contract.md) — verified by directory listing at authoring time, not assumed. `0026` is the first uncontested slot.

**Evidence.** Every number below was measured on 2026-07-28 against the live repository at working tree `82880ba`, with the IR regenerated by `dotnet run --project src/SpecScribe -- generate --spa` (1,119 pages, 193 of them in the four migrated families).

## Context

[ADR 0018](0018-transitional-ir-content-style-layer.md) established `web/assets/ir-content.css` as a **generated, bounded, scoped, enumerated** transitional layer, and Story 23.5 wired its drift gate (`npm run check:ir-content`) into CI with no `continue-on-error`. The gate re-derives the layer from `src/SpecScribe/assets/specscribe.css` and byte-compares against the committed copy.

ADR 0018 was explicit that the layer is **bounded** — "only rules whose selectors are actually used by the four migrated families' markup." What it did not say is *when* "actually used" is evaluated. The implementation answers that question the only way it easily could: it harvests class names from the markup those families render **in the IR sitting on disk at extraction time**.

That makes the committed artifact a function of three inputs, not two:

1. `specscribe.css` — committed, versioned, reviewable.
2. The four families' **templates** — committed, versioned, reviewable.
3. The **project's own planning data** — `sprint-status.yaml`, epic statuses, retrospective presence. Not an input anybody thought they were declaring.

The third dependency was not theoretical, and it failed in **both** directions on the same run:

- **False drift.** `check:ir-content` went red on 2026-07-28 with `+ .epic-remaining-review` and `- .sprint-lane-empty`. Neither rule had changed in `specscribe.css` (last touched in `559f600` and `f7c6859` respectively). What changed was that an epic entered review and every sprint lane filled up. A gate that stops the build had been tripped by ordinary sprint work on a commit that could not possibly have affected the layer.
- **Silent style loss — the worse half.** The committed sheet carried exactly **four** of the `epic-remaining-*` status variants (`active`, `done`, `drafted`, `ready`), because only those four epic statuses existed the last time somebody ran the extractor. When an epic first entered review, its dashboard tile rendered against **no `.epic-remaining-review` rule at all** and quietly lost its `border-left-color: var(--status-review)`. Nothing failed. No test could see it — the tile's markup was correct and its status word was present, so neither the byte-parity harness nor the a11y check had anything to catch.

This is the failure mode `ir-content-build.mjs` already names for manifest *fields*, in a comment block written by Story 23.5 after whole-corpus and whole-source fields had each been removed for it:

> a field belongs here only if changing it implies the emitted `ir-content.css` changed too. A field that can move on its own turns the gate red on a commit that could not possibly have affected the layer — and a gate that cannot stay green teaches people to re-run the extractor on reflex, which is exactly how a real drift gets committed unnoticed.

Two rounds of fields were removed under that rule. The rule was never applied to the **derivation itself**, which is where the same defect had been sitting the whole time — and it is strictly worse there, because a bad field only reddens CI, while a bad derivation also ships an unstyled page.

## Decision

### 1. A committed generated artifact must be a pure function of committed inputs

`ir-content.css` and its manifest may depend on `specscribe.css` and on what the migrated **templates can emit**. They may **not** depend on what the project's planning data happens to make them emit today. Restated as the working test, and deliberately phrased as an extension of the rule already in the file:

> **A generated artifact belongs in the repository only if regenerating it on a different day, from the same commit, produces the same bytes.**

Anything that fails that test is a latent CI failure and a latent silent-rendering bug, in that order of visibility and reverse order of severity.

### 2. Where a class is drawn from a closed domain, seed the domain — not the observed subset

`selectorIsUsed` asks *"does this class appear in today's markup?"*. For a data-conditional class it must ask *"can this class ever appear in markup these templates emit?"*

The seeding is **self-limiting** and that is what makes it safe rather than a return to wholesale import: a rule is still carried only when **every** class it names is present, so seeding `deferred` cannot drag `.req-card.deferred` onto a migrated page that has no `.req-card`. Measured cost of closing every domain below: **865 → 873 rules, 107.2 KB → 108.1 KB (+8 rules, +0.9 KB, +0.8 %)**. Coverage of `epic-remaining-*` went from **4 variants to 7** — the three that were latent bugs waiting for an epic to reach that status.

Three domains are closed, all of them already authored as explicit lists in C#:

| Domain | C# source | Shape in markup |
| --- | --- | --- |
| Lifecycle stages | `StatusStyles.LegendStages` (superset of `StoryStages` / `EpicStages`) | bare token beside a base class — `.status-badge.review`, `.sprint-card.active` |
| Stage-suffixed families | `Charts.cs`, `StatusStyles.AdrAccentToken` | compound name — `epic-remaining-%s`, `dn-%s-item`, `sb-%s-item`, `sb-%s-sw`, `list-row-accent-%s` |
| State-conditional singletons | `SprintTemplater`, `Charts` | emitted under a data `if` — `sprint-lane-empty`, `sprint-filter-empty`, `sprint-lane-more`, `unplanned-card`, `chart-empty` |

### 3. The interim implementation duplicates a C# vocabulary, and says so in the file

The seeding lives in `web/scripts/ir-content-lib.mjs` as `STAGES`, `STAGE_CLASS_TEMPLATES` and `CONDITIONAL_CLASSES`. **This is a hand-maintained duplicate of `StatusStyles.LegendStages`, and duplicating a list is the same class of defect this ADR fixes** — it goes stale the day an eleventh stage is added, and it goes stale *silently*, reintroducing exactly the unstyled-tile bug.

It is accepted as an interim step for one reason: it is strictly better than the status quo it replaces (which duplicated nothing but simply *omitted* six of the ten stages), and it is a single named block rather than a scatter. The duplication is called out in a `⚠️` comment at the declaration site pointing here.

### 4. The durable form is the C# side publishing its domains into the IR

The IR ([ADR 0016](0016-ir-carries-rendered-prose-html.md)) is already the one channel `web/` reads the C# side through, and `web/ir/adapter.ts` is already the one file that knows its field names. The stage vocabularies belong on it:

```jsonc
// spa/manifest.json
"vocabularies": {
  "stages": ["pending", "drafted", "ready", "active", "review", "done",
             "deferred", "unmapped", "retired", "unrecognized"]
}
```

emitted directly from `StatusStyles.LegendStages`, so a new stage reaches the extractor by construction and the duplicate in Decision 3 is deleted. This adds a field to the canonical IR contract, which is why it is an ADR rather than a patch, and why it is **proposed here rather than implemented alongside the interim fix** — it wants a `schemaVersion` bump and the owner's ratification, not a quiet append.

Stage-suffixed *templates* (`epic-remaining-%s`) and state-conditional *singletons* stay authored on the JS side even after this: they describe how `web/` composes class names, not what the C# vocabulary is.

## Consequences

- **The gate stops lying.** `check:ir-content` red now means the stylesheet or a template moved — the two things it was always meant to mean. Verified: green, and byte-identical across repeated extraction.
- **Two silent rendering bugs are closed**, one that was live (`.epic-remaining-review` unstyled while an epic sat in review) and one that regeneration would have introduced (`.sprint-lane-empty`, twelve declarations, lost the moment every lane filled).
- **+0.9 KB on a transitional layer Story 23.4 deletes.** Cheap, and it buys correctness on a surface where the alternative failure is invisible.
- **A new lifecycle stage now requires two edits until Decision 4 lands** — `StatusStyles` and `ir-content-lib.mjs`. This is a real regression in maintainability, taken knowingly, and it is the whole reason Decision 4 exists rather than the interim fix being declared sufficient.
- **The rule generalizes beyond this layer.** Any future generated-and-committed artifact — and Epic 26 is expected to add some — inherits the test in Decision 1. `check:tokens` already passes it (`:root` custom properties are authored, not data-derived); this ADR makes that a property to preserve rather than an accident.

## Alternatives considered

**Regenerate and commit whenever the gate goes red.** The status quo, and the treadmill. It does not fix the silent style loss at all — it *alternates* which bug is live, because each regeneration bakes in one data snapshot and drops the states absent from it. The 2026-07-28 regeneration demonstrated exactly this: it gained `.epic-remaining-review` and lost `.sprint-lane-empty` in the same diff. Rejected as actively harmful, not merely tedious.

**Extract from a committed fixture IR rather than the live one.** Genuinely attractive: it would make the derivation deterministic *by construction* rather than by enumerating domains, and would close conditional classes the domain lists miss. Rejected for now on cost and honesty — the repository has no committed IR fixture corpus (the golden-fingerprint harness builds its corpus in code), so this means authoring and maintaining a fixture whose realism is itself a thing that can drift. Worth revisiting if Decision 4's vocabulary channel proves insufficient; noted here so a later reader does not think it was overlooked.

**Carry the whole stylesheet and drop the bounding.** Removes the failure by removing the feature. This is precisely the shape Story 23.2 walked away from and [ADR 0018](0018-transitional-ir-content-style-layer.md) exists to avoid. Rejected.

**Widen the gate to tolerate small diffs.** A gate with a tolerance is a gate that teaches people to ignore it, and it would have hidden the unstyled-tile bug just as completely. Rejected.
