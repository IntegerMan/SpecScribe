# Architecture Decision Records

This directory holds SpecScribe's Architecture Decision Records (ADRs) — short documents that
capture a significant decision, the context that forced it, the options weighed, and the
consequences we accept. They are hand-authored (not generated from `_bmad-output/`) and are
rendered into the live site by SpecScribe itself.

Each record is numbered by its filename prefix and carries a `**Status:**` line.

- [ADR 0025 — `retired` Is a Terminal Story Stage, and the Two Status Classifiers Are Deliberately Asymmetric](0025-retired-is-a-terminal-story-stage-in-both-classifiers.md) — **Proposed** 2026-07-28 (authored by Story 8.9; **amends Story 8.2's canonical lifecycle**. Story 8.2 built two classifiers over one CSS vocabulary on purpose — `ForSprint` reads a **closed set** of `sprint-status.yaml` values, `ForStatus` reads **free text** from a story artifact's `Status:` line — and that split is kept. The defect was narrower: a word promoted to first-class in one was never promoted in the other, so a story file reading `Status: retired` (Story 22.3, retired 2026-07-27) fell through to `unrecognized`. Five consequences, the load-bearing one being that `ForEpic` gated on `All(c => c == "done")`, so **an epic that retired a story could NEVER read done** — Epic 22 permanently short of it regardless of how much shipped, propagating into `RequirementsParser.DeriveStatus`. Decides: `retired` is a **canonical stage reachable from BOTH classifiers** and **TERMINAL**, joining `StoryStages` immediately after `done` and `EpicStages` for the same reason `unrecognized` is already there — with the rule that a stage added to a partition list **must** gain its label arm in the same edit, because both label switches end `_ => "Pending"` and a class without a word is a quieter mislabel than the one being removed. The roll-up is **done-or-retired ⇒ done, all-retired ⇒ retired**, with retired **counted** in the denominator, **neutral** for the lower tiers, and excluded from the all-unrecognized test rather than blocking it; `ForEpicWithRetrospective`'s gate keys on `done` alone, so **a fully-abandoned epic is not awaiting a retrospective**. ⚠ This **deliberately diverges** from `SprintTemplater.DeliveryWheel`, which EXCLUDES retired from its denominator `M` — the wheel asks *how much of the active plan is done*, the roll-up asks *is this epic closed*; **both are right and aligning them breaks one**. The vocabulary is **six words** — `retired`/`superseded`/`deprecated`/`cancelled`/`obsolete`/`wontfix` — authored in **exactly one place**, with `EpicsParser.RetirementKeyword` building its regex from that same array instead of its old hand-maintained three-word copy; matched on the whole normalized word **before** the token fallback (so `not-retired` stays unrecognized), with `-`, `'` and `’` collapsed so `wont fix` / `won't fix` / `won’t fix` are **supported, not merely tolerated**. ⚠ `ForSprint` stays **narrower permanently**: `FreeTextBadge` consults it first, so teaching it `superseded` would flip an ADR whose status line reads exactly "Superseded" from its muted strikethrough pill to a canonical Retired badge — latent today (every ADR reads "Accepted") and kept latent by test. `AdrAccentToken` reads a **third** vocabulary including `rejected`, deliberately not unified. **No 7th `--status-*` token** (holds Story 9.3 owner decision #1): retired shares `--status-deferred`, distinct by word and class only — and since `Icons.ForStatus("retired")` and `("deferred")` are **byte-identical by design**, an icon-only assertion is vacuous. Owning no token means every theme remap is inherited for free, so **no webview carve-out was needed** — verified, not assumed. The card stays **INLINE and visibly demoted** (owner D2), not hoisted into the collapsed retired-notices `<details>`, which collects a different mechanism entirely. Costs stated: `ForStatus` now has three ways to reach a stage and their ordering is load-bearing; the widened regex changes which epics.md comments get hoisted (today's corpus has none); **quick-dev doc frontmatter reclassifies too**, a second surface the ACs did not name; and `RenderParity.StoryCardRegex` had to loosen from an exact class match to a class-attribute match. Rejected: one unified classifier (breaks ADR status pills), dropping retired from the epic denominator (loses the all-retired case), **coercing retired to `done`** (green creep at the exact place the portal must be honest), hoisting the card, and earning a 7th token)
