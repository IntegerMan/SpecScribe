## What Went Well

### The golden-fingerprint gate was lying, and the story that refused to regenerate caught it

The epic's most valuable finding is not in any story's acceptance criteria.

`SiteGeneratorAdapterTests.NormalizeVolatile` ran `FoldToday` **before** `BuildRow`, injecting a
`<date-iso>` placeholder whose leading `<` the `[^<]*` negated character class cannot cross.
`BuildRow` silently stopped matching its own row and let the **short commit SHA** through into the
hash. The constant is captured pre-commit — when the About row still shows the *previous* SHA — and
then fails the instant the work lands. It reads as a rendering regression and invites a needless
regeneration, which is exactly the move that hides it.

Story 5.2 found it by **declining to regenerate**. The fix is one character class
(`[^<]*` → `.*?`), and the proof is that the *unchanged* `aaef12dd…` constant then passed at
**two different commits**. Story 5.1's record had already reported the fingerprint "UNCHANGED"
while it was red on `main` — 5.1 was not careless; the gate was reporting a false state.

**Consequence beyond this epic:** the "golden fingerprint regeneration tax" recorded as an
accepted standing cost in the Epic 10 and Epic 19/21 retros was **partly this defect**. That cost
should be re-measured, not carried forward as an assumption.

The fix also lives *outside* Story 5.2's own File List (`SiteGeneratorAdapterTests.cs` is a shared
golden harness), and 5.2 flagged it deliberately rather than folding it in silently — the exact
discipline Epic 4's Key Insight #3 asked for.

Stories 5.1, 5.2 and 5.3 each opened with an explicit `⚠️ Critical framing` block saying so. The

### Load-bearing decisions were reasoned in public, not just made

Several choices in this epic were the non-obvious one and said why:

- **The machine summary line bypasses Spectre entirely** (`Console.Out.WriteLine`). Spectre
  word-wraps at the profile width — 80 columns once stdout is redirected — and would split the
  very record CI is meant to grep as a unit. A test asserts the line carries no control characters.
- **`--show-config` emits one line per field**, not the packed line the task sketched, because path
  values contain spaces and a packed line cannot be split back without a quoting scheme. `value=`
  is last, so everything after it is the value.
- **`CliOverrides.Capture` must run before `SettingsStore.ApplyTo`**, because `ApplyTo` fills nulls
  *in place* — after it, a CLI value is indistinguishable from a restored one. This is also why the
  interactive menu loads once at entry.
- **5.5 kept the date cutoff separate from the dashboard's artifact-staleness `today`.** Conflating
  them would let `--today-policy last-commit` on a long-idle repo report every planning artifact as
  freshly updated.
- **5.6 restructured `HowToReadTemplater`'s honesty gate** rather than appending into it. Adding an
  always-renders section to the single `sections` builder would have made `sections.Length > 0`
  permanently true and killed the degraded branch — promising a reading order and glossary to an
  undetected repo that has neither.
- **5.6 declined to describe `.specscribe` as "gitignored"** as its task text asked, because
  SpecScribe writes no `.gitignore` entry; that claim would be false in shared chrome for any
  project that hasn't added one by hand.

## Challenges

### 1. The crash guard was fixed, reviewed, and still wrong

Story 5.3's original `RunGuarded` guarded the generator call and then handed the result to
`_onEvent` **outside** the try. `_onEvent` is a caller-supplied delegate invoked on the same
unguarded ThreadPool thread — in production `ConsoleUi.LogEvent`, which writes to the console. Pipe
`specscribe watch` into a process that exits first, stdout closes, `IOException`, process death.

That failure is **worse than the one first fixed**, because it fires on the **success** path: a
perfectly good rebuild kills the session while reporting itself. Inspection did not find it. The
first review did not find it. An **owner-requested audit of the guard class** did.

The remedy is now structural: every event leaves through one `SafeNotify` seam (the swallow is
deliberate — the reporting channel *is* the thing that failed), all raw `FileSystemWatcher`
handlers are wrapped in `SafeHandle`, and the timer bodies were extracted to
`RunDebouncedPass`/`RunTopologyPass` internal seams **because these guards only matter where there
is no caller**: testing them through a real `Timer` means a regression takes down the *test host*
rather than failing an assertion, turning one broken guard into a lost suite run reported as
infrastructure noise.

### 2. Five tests passed while exercising nothing

| Story | Test | What it actually proved |
|---|---|---|
| 5.1 | `GenerationRun_SurfacesTheExitCodeGenerateCommandReturns` | Re-exercised trivial computed properties already covered above it; named for integration coverage it never had |
| 5.3 | `ThrowingEventCallback_DoesNotEscapeTheConfigDirHandler` | Never removed the directory — `CreateWatcher` succeeded, the success path never called `_onEvent`, `Assert.Null(ex)` passed without touching the guard |
| 5.3 | `BurstOfSaves_CoalescesAndLeavesCoherentOutput` | Asserted final on-disk content and absence of `Error` events only; disabling debouncing entirely would still pass |
| 5.3 (dev pass) | first fault injection | Created a **directory** named `as-directory.md` assuming the read would fail — `File.Exists` returns false for a directory, so the route took a tidy `Skipped`. Green, exercising nothing |
| 5.5 | `OneResolvedToday_MakesEveryConsumerAgree` | Proved a pure function is referentially transparent; never touched `SiteGenerator._today`, `CommitHeatmap`, or `GitPulsePanel` — the real call sites the AC is about |

Four were caught by review, one by the dev pass itself. **The remedy 5.3 established is the
pattern worth generalizing:** pair the fix with a **counter-test**, so the guard cannot be
satisfied by swallowing everything.

One trap is worth recording verbatim from 5.3's review, because two attempts failed on it: an
event's `RelativePath` is the **source-relative `.md` path with the OS separator**, not the
normalized forward-slash `.html` output path.

### 3. Scope-by-File-List degraded under five siblings sharing the same files

CLAUDE.md prescribes scoping reviews by story File List rather than commit range. Story 5.5's
review found that insufficient and said so outright: several of its 18 files
(`SiteGenerator.cs`, `Charts.cs`, `SettingsStore.cs`, `Commands.cs`,
`HtmlRenderAdapter.Dashboard.cs`) are **also shared by sibling stories on the same commit range**.

It fell back to **content attribution by hunk** — excluding Story 5.2's ADR-0014 folder migration
and `CliOverrides` predicate fixes, Story 5.3's `CopyEmbeddedAsset` retry, and Epic 20/23/25
content — and **declared those exclusions in the review record** rather than itemizing them as
deferred work. That adaptation was invented on the spot and is not written down anywhere.

### 4. The interactive TTY path cannot be driven by any agent harness

Stories 5.1, 5.2 and 5.5 each recorded the identical verification limit: every tool harness
captures stdout, so Spectre always reports `Interactive == false`. The unexercised surfaces were
the logo / live progress bars / rounded table / clickable output link (5.1), the interactive menu
loop and the new "Include the repository README?" confirm prompt (5.2), and the
`SelectionPrompt<DatePolicy>` (5.5).

**There is no CLI analogue to the Epic 19/21 "verify it in a live browser" action item.**
The Project Lead confirmed at this retrospective that these surfaces **have been verified live**,
which closes the gap for Epic 5 — but the structural blind spot remains for every future CLI story,
and it is why the missing Spectre/`CommandContext` harness became Action Item 1.

### 5. Shared-`main` cost, twice

- Story 5.6's verification was blocked by an unrelated concurrent session's build failure in
  `ImpactMapTemplater.cs` / `Charts.cs` / `HierarchyExplorer.cs` / `DashboardViewBuilder.cs` — none
  touched by that story. It cleared, and 5.6 re-verified rather than reporting around it.
- Story 5.3 **deliberately left the golden fingerprint red**, correctly attributing the drift to
  Story 20.3's uncommitted mid-flight work and declining to lock a hash onto another session's
  incomplete state. The right call — and it means the epic carried a red gate for a window.
- Story 5.3 also owned its *own* contribution to the standing git-fixture flake: an uncapped
  `Parallel.For(0,12)` of full rebuilds was starving the git tests. Capping to
  `MaxDegreeOfParallelism = 4` took the failure count 17 → 8 and the run 5m01s → 2m39s.

### 6. Two deferred items are the same missing harness

Story 5.1 deferred both AC #3's interactive/non-interactive branching coverage **and**
`GenerateCommand.Execute`/`RunGeneration`'s end-to-end return-wiring. In `deferred-work.md` they
sit as two unrelated-looking lines. They need **one** thing: a `Spectre.Console.Testing` /
`CommandContext` harness that does not exist in this test project.

### The 19/21 reframe was confirmed by inversion

The Epic 19+21 retrospective found *every* story needed at least one post-implementation revision
round, and reframed those rounds as the designed workflow whose size is set by elicitation depth.

Epic 5 had essentially **one** — Story 5.3's owner-requested crash-guard audit, which found a real

That is not because these stories were better written. It is because Epic 5 is a CLI and

story quality** — which is precisely what the 19/21 reframe claimed, now tested from the other
direction.

## Key Takeaways

1. **When the golden hash moves and you did not touch rendering, audit the normalizer before you
   regenerate.** Regeneration is the move that hides a broken harness. Story 5.2 found a defect
   that had been silently drifting the constant on every commit, and the proof was an *unchanged*
   constant passing at two commits.
2. **A test's prose is not its coverage.** Five tests in this epic passed while never reaching the
   branch their name claimed. Grep the docstring against the asserts, and pair every guard fix with
   a counter-test so it cannot be satisfied by swallowing everything.
3. **A guard added at one seam is not a guarded path.** 5.3's crash fix was incomplete in a way
   that made the *success* path fatal. Guards need an audit of the whole call path, and the seams
   need to be drivable synchronously — a guard tested through a real `Timer` turns a regression into
   a lost suite run reported as infrastructure noise.
4. **Framing a story as hardening changes what the dev pass does.** 5.3 discovered two of its four
   tasks were already shipped by Story 6.11 and closed the real gap instead of building a redundant
   route. The framing is what made "already done" a legitimate finding rather than a skipped task.
5. **Scope-by-File-List has a second tier and it was never written down.** When siblings share both
   the commit range and the files, attribution has to drop to the hunk — and the exclusions have to
   be declared in the review record.
6. **The interactive TTY is a permanent verification blind spot for agents.** Three stories recorded
   the identical limit. The owner closed it by hand this time; the durable answer is test
   infrastructure, and it is the same infrastructure that closes both of Story 5.1's deferrals.

## Significant Discoveries

**1. The golden-fingerprint regeneration tax is partly a defect, not a cost.** Two prior
retrospectives recorded it as an accepted standing tax of a byte-exactness invariant the project
genuinely wants. Some unknown fraction of it was the `NormalizeVolatile` bug, now fixed. This does
not invalidate any epic plan, but it does mean the figure should be re-measured before it is cited
again as evidence.

**2. Epic 5's two deferred test-infra items are one item.** Recorded so Story 17.1/17.3 triage does
not schedule them as two.

**3. A named, argument-bearing date policy is the first case `DatePolicy` cannot represent.**
`DatePolicy` is currently a bare enum; `--as-of <date>` carries a value. Story 5.7 will need a shape
change (enum + optional date, or a small record) across `DatePolicy.cs`, `SiteSettings.cs`,
`SettingsStore.cs`, `SettingsResolver.cs`, `DiagnosticsTemplater.cs` and `Commands.cs`. This is
flagged at seeding rather than discovered in the dev pass. Persistence must reuse
`DatePolicyJsonConverter`'s forgiving vocabulary — a policy carrying an arbitrary date *string*
widens the blast radius of the whole-document-deserialization failure 5.5's review already fixed.

**No epic plan is invalidated.** Epic 17's sequencing line (*"after … Epic 5 (CLI)"*) is satisfied
by the five shipped stories; Story 5.7 is additive and non-blocking.
