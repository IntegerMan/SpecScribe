## 3. Patch

Ordered by severity. Every one verified live at HEAD.

### High

**F-1 — Family regions are composed LAZILY, violating this story's own central invariant; one run can emit two
different regions for the same page.** *(edge-C#; contradicted by blind-C#, resolved in edge-C#'s favour by
direct verification)*
`WritePage` composes and linkifies the region at write time, and `CapturedPageView.Region`'s own comment
explains why deferring it is a defect: `ApplyReferenceLinks` reads mutable state, and `CodeReferenceLinkifier`
no-ops on an empty `_codePages` but **strips unresolvable view-source anchors** once populated (measured at 77
bytes on `readme.html`). `AddSpaSurface` [SiteGenerator.cs:4504] and `WebviewSurfaceFor` [:4323] do **not**
obey it — they compose *and* linkify at bundle-build time. Verified reachable: `OnFirstPaintReady` fires at
[:773] and `RenderWebviewSurfaces` is documented as callable from it [:329], while `_codePages` is not
populated until [:2808]. So the webview's dashboard/epics regions can be linkified against an **empty**
`_codePages` while the end-of-pass `EmitSpaSite` → `BuildSpaBundle` → `AddSpaSurface` linkifies the *same five
pages* against a **populated** one. The composed-vs-sliced oracle that would have caught this is retired.
**Fix:** route the family path through the same eager seam, or hoist the composition to write time.

**F-2 — `TrimEnd` asymmetry puts two region shapes back into one IR.** *(edge-C#, blind-C#)*
`WritePage` calls `.TrimEnd()` [:4396]; `AddSpaSurface` does not [:4504]. All 31 templaters end bodies with
`</main>\n\n`, so long-tail regions end `</main>` and the five family regions end `</main>\n\n`.
`SpaDelivery.SchemaVersion` was bumped to **2** specifically to give the IR *one* region shape; this
reintroduces a second along a new axis, moving `contentHash` and per-page byte accounting for the family
routes relative to every other route. **Also fix the comment** at [:4395]: `TrimEnd` is documented as
"replication of the slice's `</main>` boundary", which is false — the slice *truncated* at the closer,
`TrimEnd` keeps everything after it (that is what recovers the lightbox, and it is a different rule).

**F-3 — ADR 0013's text-twin contract is enforced on 1 of the 9 chart-bearing pages.** *(edge-web)*
`enforce(dashboardContract(...))` appears **only** in `DashboardSurface.vue:36` — verified, it is the sole call
site. The 8 `insight` singletons (`impact-map`, `risk-quadrant`, `work-graph`, `code-map`, `git-insights`,
`deep-analytics`, `cadence`, `traceability`) all carry chart mounts and get no warn, no error, no gate.
`InsightSurface.vue`'s doc comment claims the twin "survives here by construction" — construction is exactly
what is unchecked. CLAUDE.md makes "every chart needs an accessible text equivalent" a project rule; the
contract is even *named* `dashboardContract`, so this is structural rather than a missed call site.

**F-4 — The story's only defence against a silent `pass-through` regression can be disabled by an env var, and
passes vacuously on an empty manifest.** *(blind-web, edge-web)*
[web/test/families.test.ts:23] `process.env.SPECSCRIBE_IR_DIR ?? join(..., 'SpecScribeOutput', 'spa')` — the
default branch appends `spa/`, the env branch does **not**, while every other consumer treats the variable as
the output **root** and appends `spa/` itself (`ir/adapter.ts:57`, `ir-content-lib.mjs:649`,
`NuxtPrerender.cs:469`). Setting it — the documented way to point the suite at another checkout, and what
`render-lib.mjs` and `experiment-two-ir.mjs` do — makes `existsSync` false, `manifest` null, and
`describe.skipIf` **skip**. A skip is green. Separately [:84], with `manifest.pages === {}` the loop body never
runs, `stragglers` is `[]`, and the assertion passes having classified nothing — the project already wrote the
guard for this class twice (`validateOracle` at `parity-lib.mjs:103`, `SHARED_PRIMITIVES.length > 0` at
`ir-content-lib.test.mjs:2262`) and did not apply it here.

**F-5 — `measure:parity` can exit 0 while measuring nothing; four independent defaults each convert "missing"
into "matching".** *(blind-web, edge-web, auditor — 8 findings merged)*
1. `mainRegion(...) ?? ''` on both sides [measure-parity.mjs:116] — a regex miss collapses to `'' === ''` and
   scores a **green row with `goldenBytes: 0`**. 23.4 both narrowed the pattern to require `id` as the *first*
   attribute [harness-lib.mjs:63] and widened the corpus 193 → 1,469, which is what makes it reachable.
2. `verbatim = nuxtHtml.includes(page.region.mainInnerHtml)` [:122] — `.includes('')` is **always true**, and
   `splitContentRegion` returns `mainInnerHtml: ''` for every `degraded` page. Such a page then scores
   `irVsNuxt` *and* `verbatim` true and is filed at [:150] as an **inherited capture delta owned by Epic 22**.
   The one row shape where the IR is provably wrong scores as the cleanest.
3. `NO GOLDEN` rows are excluded from `measured` [:161] and do **not** increment `missingOutput`, so with every
   golden page absent the TOTAL prints `0/0` and the harness exits 0.
4. An IR-only divergence (`goldenVsIr` false *and* `irVsNuxt` false while `goldenVsNuxt` true) is never pushed
   as a delta [:143] and never affects the exit code — precisely where a composed-region defect lands.
Additionally the committed per-page digest oracle is **written by this script and read by nothing** — no
script, test or CI step ever compares `goldenSha`/`irSha`/`nuxtSha` back, so every run overwrites it and a
regression re-pins itself. (The record calls it "sha256"; it stores a 64-bit truncation, [:89].)
*Mitigating:* 23.6 superseded this with `check:parity` + `parity-pinned.json`, and `measure:parity` is not in
CI — but it is still in `package.json`, still exits 0, and AC #1's evidence rests on it.

**F-6 — `AssetManifest.HierarchyBootInline` and `ExtraHead` are write-only; the three head shapes 23.4 modelled
are collapsed back to one derived boolean.** *(edge-C#)*
Verified: five setters (`EpicsTemplater` ×4, `HtmlTemplater`) and zero production readers; `ExtraHead`'s only
reader is a test assertion. Their sole consumer, `HtmlRenderAdapter.Render`, was deleted by 23.6, and Nuxt now

script on `code-map.html` anyway, because the page does carry `data-hierarchy`. The anti-flash handshake now
runs on a page the C# side deliberately excluded from it. **Either** route the fields into the IR **or** delete
them and their doc comments; leaving them is dead configuration a reader will trust.
