## What Went Well

**Plotly adoption paid for itself across the epic.** ADR 0012 reversed 20.1's own spike conclusion a day after it was written, and every downstream story (20.5, 20.7, 20.9) inherited the bundle recipe (standard bundle, `plotly_afterplot` event, class-list color resolver) without re-deriving it. Net effect: −4.79 MB on the portal and nine hand-rolled arc renderers deleted — the exact drift ADR 0010 §6 had tried and failed to prevent as a convention, finally closed by making it a shared component instead.

**20.2's event seams compounded cleanly.** The `specscribe:explorer-select` / `specscribe:content-swapped` seams, minted once in Story 20.2, were explicitly *adopted* — never re-minted — by 20.3, 20.5, 20.7, 20.8, and 20.9. The clearest example in this epic of an early decision paying off repeatedly rather than needing rediscovery.

**NFR8/live-browser-verification discipline held, and validated strongly.** Every story from 20.2 onward caught at least one defect invisible to the ~2,000+ test suite by opening the rendered page: a keyboard-focusable hidden SVG link (20.2), tooltip/selection-state desync (20.5), duplicated-word screen-reader announcements ("Epic Epic 19", 20.3), CSP violations that never surface in a console capture (20.4, 20.6). This is the strongest validation yet of the Epic 19/21 retro's live-browser-verification action item.

## Challenges

### 1. Every story from 20.2 onward shipped a live-browser-only defect

Named above as a win for the *practice* that caught them — but it is also a real cost signal: this class of defect (focus/ARIA/CSP/state-desync) recurred in nearly every story regardless of author care, because the test suite structurally cannot see it. Accepted as the ongoing cost of a JS-heavy, accessibility-conscious chart surface; no new action proposed, the existing verification step is working as designed.

### 2. Completion-Notes claims repeatedly didn't survive verification

20.1, 20.2, and 20.7 each explicitly recorded a case where a Completion Notes claim ("zero console errors," an exact byte count, "byte-identical") was contradicted once someone actually looked. None were caught by re-reading the notes; all were caught by live verification or a fresh reviewer re-deriving the number. Treated as further evidence for practice #3 above rather than a new problem.

### 3. Elicitation-depth pattern recurred a fourth time — **closed this retrospective, not remedied**

20.1's spike declined Plotly, reversed by owner correct-course the next day into ADR 0012/0013. 20.3 shipped a full-width related-work list, redirected to a minimal card rail after the owner saw it rendered. 20.8 reversed its own same-day decision once better data showed the "duplication" it removed cost 17× less than what it added. This is the same open item carried since Epic 3, recurring across Epics 3, 6, 7, 9, 19, 21, and now 20.

**Owner decision, this retrospective:** the item is **closed as accepted workflow**, not carried forward for a fifth epic. The redesign-after-seeing-it-rendered pattern is how the owner intends to work — see is-it-right-when-rendered, redirect, iterate — not a defect that deeper create-story elicitation should engineer away. See Action Items.

### 4. ADR 0013's per-story text-twin gate had no durable owner going into future epics — **resolved this retrospective**

ADR 0030 (ratified the day before this retro) named the gap directly: no Epic 24 story owns the text-twin audit required before `Charts.ReferenceGraph`'s SVG can retire. At this retrospective, the owner identified the underlying cause directly: with exactly one confirmed consumer of the product right now, and the current priority being a polished, minimal happy-path core UX, auditing every new hierarchy surface's twin inline was pulling ordinary feature stories toward accessibility breadth instead of UX depth.

**Resolved via [ADR 0031](../../docs/adrs/0031-text-twin-standardization-moves-to-its-own-epic.md)**, ratified in this session: ADR 0013's hard per-story gate is retired for new work (NFR-5's wording is unchanged); text-twin/JS-off standardization becomes the scope of a new, dedicated **Epic 28** (seated in `epics.md`/`sprint-status.yaml`, unscheduled, no stories yet), which will prove a standardized pattern on one surface, verify it live, then broaden — the same spike → component → site-wide-rollout shape Epic 20 itself used for the chart engine. This directly resolves ADR 0030's named open item: Epic 24 does not own the audit; Epic 28 does. Already-audited surfaces (dashboard, story detail, Code Map, Impact Map, Git Insights) are unaffected.

## Key Takeaways

1. **A foundational spike can be wrong and get corrected fast, without costing the epic.** 20.1 declined Plotly; ADR 0012/0013 reversed it a day later. The cost was contained because nothing downstream had been built against the wrong conclusion yet.
2. **Shared seams compound; shared conventions don't.** 20.2's event seams were reused five times without reinvention. ADR 0010 §6 asked for the same discipline as a *convention* and got three independent arc renderers instead. The lesson generalizes: prefer a shared component over a shared rule wherever both are possible.
3. **Live-browser verification is proven, not just adopted.** Every visual story in this epic found something the suite couldn't. This practice should be treated as load-bearing, not optional polish, for any future chart/interactive work.
4. **Not every recurring pattern needs a remedy.** The elicitation-depth item recurred a fourth time and was closed as *accepted workflow* rather than driven toward a fifth fix attempt — the owner's actual intent was surfaced and named, rather than assumed.
5. **A cross-cutting contract needs a durable owner, or it becomes an unowned gate on whichever story trips over it next.** ADR 0013's per-story gate had no owner once Epic 20 closed; ADR 0030 found the gap once, ADR 0031 gives it a permanent home in Epic 28.
